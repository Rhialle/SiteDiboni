# Plano 2.2: código de barras pela câmera — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** botão **Câmera** na contagem do inventário e no balcão, que lê o código de barras pela câmera (Android e iPhone) e entrega o código à busca; e a contagem achando o produto pelo código do pacote.

**Architecture:** componente de cliente `LeitorDeCodigo` com `barcode-detector/ponyfill` (zxing-wasm) carregado só ao tocar no botão (import dinâmico); o `.wasm` é copiado de `node_modules` para `public/leitor/` num `postinstall` e servido pelo site. A busca da contagem (`itens_para_contar`) ganha o código da forma numa migração nova.

**Tech Stack:** Next.js 16.4, `barcode-detector@3.2.3`, Postgres/pgTAP, Vitest, Playwright (câmera falsa do Chromium).

**Spec:** [docs/superpowers/specs/2026-11-23-fase-2-2-camera-design.md](../specs/2026-11-23-fase-2-2-camera-design.md)

## Global Constraints

- `barcode-detector` na versão exata **3.2.3**; depois de instalar, `npm run deps:regenerar`.
- Formatos: `ean_13`, `ean_8`, `upc_a`, `upc_e`, `code_128`.
- O `.wasm` vem do próprio site (`/leitor/zxing_reader.wasm`), nunca de CDN.
- Nenhuma imagem sai do aparelho; o vídeo é parado (todas as trilhas) ao fechar, ao ler e ao sair da tela.
- `itens_para_contar` já está no banco de teste: muda por migração nova (`create or replace`), sem editar a antiga.
- Ramo `fase-2-2-camera`, saindo do `main`; nada no `main` sem o OK do usuário.

## Review Focus

1. Sair da tela (voltar, trocar de página) com a câmera aberta: a câmera desliga (a luz do celular apaga). Coberto pelo `useEffect` de limpeza da Task 3 e por teste de tela que fecha a janela e confere que nenhuma trilha ficou viva.
2. Permissão negada: aparece a mensagem, sem tela quebrada. Teste de tela com a permissão de câmera negada.
3. Código lido com espaço ou quebra de linha no fim: a busca usa o código limpo. Teste unitário na Task 2.
4. Código de pacote na contagem: acha a variação do pacote. Teste de banco na Task 1.
5. Duas leituras seguidas do mesmo código no mesmo quadro: entrega uma vez só (fecha ao ler). Coberto pelo componente fechar na primeira leitura.
